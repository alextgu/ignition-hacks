# Prompt 5 — World embed (supersedes the world half of prompt 2)

**Send this instead of prompt 2's `generate-world` / `poll-world` sections.**

Since prompt 2 was written, the Sites backend took ownership of World Labs
generation end to end: it starts exactly one Marble generation per event at
creation, persists every asset, polls the operation on a 10-second throttle,
and serves a finished, embeddable canvas. Base44 rebuilding any of that would
start a **second** chargeable generation for the same event.

So Base44's job is now one iframe.

---

## Paste this into Base44

> Add the event's shared world to the UI. **Do not** create a World entity,
> a `generate-world` or `poll-world` function, a World Labs API key, or any
> polling — the backend already does all of it. You are embedding a finished
> page.
>
> `POST /api/events` now returns a `worldUrl` alongside `guestUrl` and
> `manageUrl`. Store it on the event as `world_url`. For events created
> before this field existed, fall back to
> `${SITES_ORIGIN}/world/${event.public_slug}`.
>
> Show it in three places:
>
> 1. **Create-success screen** — under the shareable links.
> 2. **Guest page** — above the RSVP form, so guests see the world before
>    they answer.
> 3. **Host studio** — alongside the consensus summary.
>
> Use exactly this embed:
>
> ```html
> <iframe
>   src="{world_url}"
>   title="Interactive world for {event.title}"
>   loading="lazy"
>   allow="fullscreen"
>   style="width:100%; aspect-ratio:16/10; max-height:60vh; border:0; border-radius:12px; background:#0b0a09;"
> ></iframe>
> ```
>
> On narrow screens use `aspect-ratio: 4/3`. Give the iframe a fixed aspect
> ratio rather than a fluid height so the surrounding layout does not reflow
> when it loads.
>
> The page inside handles everything else: it renders the generated world
> when it is ready, an event-specific planet while generation is still
> running, adds one light per RSVP as guests answer, and labels its own
> state. **Do not add your own caption claiming the world was generated by
> World Labs** — the canvas says so itself, and only when it is true.
>
> Nothing else changes. No new secrets, no new entities, no new functions.

## Why the canvas labels itself

The canvas shows "World Labs world" only when a real API key produced that
specific world. Without a key — or for a world made by the offline fallback
before a key was added — it says "Preview world" instead. That distinction is
deliberate: presenting the fallback as generated output would be a false
claim to judges. Any caption Base44 adds on top would bypass it, which is why
the prompt above forbids one.

## What the backend exposes, if Base44 ever needs the raw state

`GET /api/events/{slug}/world` returns redacted canvas state — status, the
asset URLs, stage, and attendee lights. It carries no management token, guest
id, operation id, provider error, or full-resolution splat URL. The iframe
already consumes this; Base44 should not need to call it directly.
